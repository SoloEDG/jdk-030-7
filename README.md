# 栈闩工房

机关推箱子纯前端工房。既有不同箱材触发踏板、门闩和地板变形的关卡，也有按真实重量、绳长、动滑轮和楼层身份分流的吊盘关卡。记录步数并保存已完成关卡的最佳成绩。

## 吊盘称重怎么算

吊盘关的状态全部在 `src/shared/hoist.ts` 与 `src/features/hoist/`：

- 关卡声明三股绳的总长、两个固定端点、动滑轮位置；一个吊盘可被两股绳共同托住，联绳会让多个吊盘的层位互相约束。
- 每个吊盘有独立的 `minFloor`、`maxFloor` 和整数 `stops`。求解器枚举所有整层组合，再用绳段欧氏长度核对：`实际绳路长度 <= 绳总长`，余量记为松绳；绳不能提供“顶”的支撑。
- 限位只通过该盘自己的合法停点生效，不会把“多走的位移”平均分给其他盘。
- 合法停法先比较重力能量 `Σ(盘自重 + 厢内箱重) × 楼层`，再比较相对投箱前的总层位移；仍同优时进入 `choosing`，必须在层位图点选一组并落锁。
- 落锁前 `hoist.busy = true`，移动引擎直接返回 `reason: "busy"`；自动停法有约 850ms 的停稳演示，同优停法则一直锁定到玩家手动落锁。
- 主画布用绿框标出当前承载的厢格和托绳色条；右侧 SVG 层位图标出固定端点、动滑轮、共同托绳、目标层位虚影、松绳余量和换层盘。
- 订单和秤板都有独立 `floor`。箱子即使 `(x, y)` 与接口完全一致，`box.floor !== order.floor` 时只会显示“错层拒收”，不会签收或通关。
- 箱子离开秤板/踏板后会立即重新计算踏板供电与相邻门闩；吊盘落锁后还会再次核对称重订单和通关条件。

推荐先玩前两关：

1. **吊盘称重分流**：在右侧把铁箱向西推入乙盘，可看到甲盘、乙盘一起换层以及左绳变松；铁箱交到 `(11,6)` 的 0 层秤板后，再把木箱推入甲盘并退回 `(5,5)` 的 1 层木秤板。
2. **同优层位锁**：第一次推箱会出现三组同能量、同位移方案。选择 `1F / 1F` 才能让东侧平面接口签收；选 `0F / 2F` 或 `2F / 0F` 会演示坐标对齐但楼层接错的拒收。

## 本地运行

```bash
npm install
npm run dev
```

类型检查与生产构建：

```bash
npm run typecheck
npm run build
```

## Docker

```bash
docker compose up --build
```

浏览器打开 http://127.0.0.1:8030
